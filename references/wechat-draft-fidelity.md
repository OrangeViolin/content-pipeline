# 公众号正文保真

这份说明管的是公众号正文，不管小红书卡片或播客封面。自动脚本只处理本地字符串。保存草稿、重开编辑器、用手机阅读，都要人做。脚本通过不等于线上已经看过。

## 连续主题底板

只给每个段落或每个 `section` 上底色不够。兄弟块之间的 margin，以及列表项自己的 margin，会落在这些底色外面，底下的页面颜色就露出来。

稳定写法是把整段正文包进同一个 `section`，并写内联样式：

```html
<section style="background-color:#F2EDE3;padding:1px 0;">
  …原来的正文…
</section>
```

`background-color` 用当前品牌的底板色。01fish 是 `#F2EDE3`，其他品牌换自己的色，不要沿用这一个。`padding:1px 0` 让首尾 margin 也留在这块底色里面。保存再打开后，编辑器可能去掉 `id`，内联 `style` 还在；白缝是否消失，要以重开后的实际预览为准。

预览页 `body` 上的背景只供本地浏览。复制进编辑器的是 `.content` 里面的片段。不要把 body 背景当成已经粘进去的背景。

生成器在 `scripts/md2wechat_formatter.py` 里做这层包裹。已经手改过的稿不要为此整篇重排，用下面的离线工作台，在明确按钮之后再包。

## 手改稿

线上编辑器里当前的富文本是唯一基线。修订或换图之前先备份。不要用旧 Markdown、旧的本地 HTML 覆盖这次手改。

顺序：

1. 在公众号正文里复制。
2. 打开 `scripts/wechat-draft-workbench.html`。这个页面没有外链，也不在加载时读剪贴板。
3. 聚焦接收区再粘贴，或自己选择一个本地文件。页面从 paste 事件读取 `text/html` 和 `text/plain`。没有 `text/html`、没有剪贴板数据、或权限被拒绝时，停止，不用纯文本冒充富文本。
4. 下载基线快照。
5. 只改指定的底板或图片。外部 HTML 只当数据；页面不把原稿插进 DOM，复制出去之前去掉 `script`、内嵌框架和 `on*` 事件。
6. 审计。通过按钮用 `ClipboardItem` 写入 `text/html` 和 `text/plain`。浏览器没有这个 API，或写入被拒绝，就停止，不要换一种方式假装已经复制。
7. 在编辑器里手动粘贴，保存，重开，看实际预览。再备份一次，和上一份比较。

工作台不注入脚本，不调用公众号内部接口，也不读取会话 token。可重复的字段比较在 `scripts/wechat_fidelity.py`。两条路径都只说明结构是否一致。

`draft/add` 只会新建一篇草稿。它不更新你正在编辑的那一篇，也不是发布。手改过的稿走工作台，不要再拿旧文件新建一篇盖回去。

## 回归审计

比较这两份 HTML 时，逐项看，不要用一个字数或一个数量代替：

| 项目 | 怎么算一致 |
| --- | --- |
| 可见正文和标点 | 去掉全部空白后的字符序列一致。只多了换行、或只因包裹/序列化多了空白，要单独注明，不算改字 |
| 图片 | URL 和顺序一致。换图时必须给出显式的预期映射 |
| 加粗 | 加粗文本的范围还在，并记录有效颜色。自身没有颜色时，用父级继承到的颜色 |
| 链接 | 地址和可见文字都一致 |
| 表格 | 每个单元格的原文一致。旧稿里的表被拿掉，要列出被拿掉的格子 |
| 主题底板 | 最外层带纵向 padding 的底板色一致。允许的新增要显式打开 |

报告写明具体片段。`ok` 只表示这些字段对得上。`phone_verified` 在自动结果里始终是 false。

## 表格

Markdown 稿里的表格仍是事实结构。写进公众号正文时默认不再输出 HTML `<table>`。

新生成的正文会把每个表换成「待配图」块，块里保留题注、表头、每一格，以及能识别出的来源或统计口径。这个块表示还没完成，不能把文章说成可以发。信息多就拆成多张图，不要把字号压小，也不要截断句子。

`table_to_svg_cards` 能生成可编辑 SVG，宽度 390。它不导出 PNG，不上传 CDN，也没有做手机阅读验收。本仓库没有栅格化依赖，不能把 SVG 说成已经完成的配图。后续门槛是：导出清晰 PNG、上传官方 CDN、按锚点替换待配图块、人在手机上看。

不要再把 `overflow-x` 横滑表格当作正文方案。本地预览里表格没溢出，也不能代替手机上的实际阅读。

旧稿里的表用 `migration_scope` 只列出范围。没有作者授权，不删除表格，也不改写用户的句子。整篇正文不能收成图片；只有这些表的内容改成配图，其余文字保持可编辑。

## 图片

换图按「这段可见文字 + 这张图」定位。锚点必须唯一，并且落在锚点之后、下一个标题之前。范围内不是正好一张匹配的图，就停止，不按序号猜。替换只改 `src`，不删掉外面的底板，也不改周围的文字、加粗和来源。

新增、替换、保留都写入 manifest：动作、锚点、旧 URL、新 URL。

封面按约 2.35:1 居中裁切，方图缩略图按 1:1 另裁一次。两次都保持缩放 1，不把一边拉长。草稿 API 只有一个封面文件位，传入的 `cover_image` 必须已经是约 2.35:1 的那一张；没有这张图时，不会改用正文图片列表里的第一张。用户自己的照片保持自然比例。重绘的图统一宽度、字号和留白，优先可编辑矢量，再导出清晰 PNG，按 390px 宽做阅读验收。截图被局部放大时拒绝使用。

能算作草稿图片成功的地址，只有 `https://mmbiz.qpic.cn` 和 `https://mmbiz.qlogo.cn`。`file:`、`data:`、`blob:` 和本地路径可以留在本地预览，不能当成已经上传。

重开后看开头、中间和结尾：底板还在，图片张数和顺序与 manifest 一致。这一步是人工的。

## 署名、草稿和运行环境

排版协助不改作者。作者栏只填写用户给出的真实署名；没给就留空，不要改成模型名。AI 确实写了正文时，正文里的诚实标注照旧保留。真人写的稿，署名保持真人。

新建草稿和编辑现稿是两件事。保存草稿也不是发布。

公众号的可执行回退：

1. L0：API 新建草稿。
2. 凭证没有配好、调用失败，或这次是预览：停在 L3，给出文件，由人复制。
3. 不因为 API 已经连上但失败，就自动改走浏览器或 CDP。只有用户当次明确要求，才可以另走浏览器。

小红书、即刻、小宇宙、抖音仍按各自实现使用 CDP：能自动提交是 L1，需要登录或选择器失效时是 L2，浏览器起不来是 L3。这几级不要套回公众号的 API 失败路径。

Grok Bot 里操作真实网页桌面时用 computerUse。不要用 Shell、CDP 或 Playwright 驱动已经登录的会话，也不要读取 cookies 或内部接口。这个限制不删除其他环境里的 `distribute.ts` 和 `wechat-api.ts`；那些 CLI 仍给对应环境使用。

## 粘贴与重开时看什么

人工验收至少看这些，自动测试不会代做：

- 复制的是正文，不是浏览器窗口的底色。
- 重开后首、中、尾的底板没有白缝，`id` 消失与否不影响内联背景。
- 列表和相邻小节之间没有露出页面底色。
- 图片数量、顺序和锚点映射一致，地址是官方 CDN。
- 待配图块已经换成图，格子里的事实和口径还在，正文其余部分仍可编辑。
- 作者栏没有被改成 AI。
- 草稿箱里的结果没有被发布。
